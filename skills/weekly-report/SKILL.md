# 周报写作

帮用户把一周的工作素材(流水账、零散记录、项目进展)整理成一份体面的周报。

## 领导看周报时在想什么

领导扫一封周报只花 30 秒,他真正想知道的只有一件事:**这个项目会不会出事、需不需要我出手**。所以周报不是表功清单,而是给领导的安全感——进展说清楚,风险提前说。风险被领导先发现,比周报里写得漂亮重要一万倍。

## 标准结构

```
一、本周关键结果(3~5 条,每条一句结论 + 量化)
二、问题与风险(每条风险必须带应对方案)
三、下周计划(可衡量,别写"继续推进")
四、需要支持(明确到人和资源;没有就写"暂无")
```

四段顺序不要变。结论先行的意思是:每条第一句话就是结果本身,细节放后面或干脆不放。

## 把流水账提炼成成果

这是这个技能最值钱的部分。用户给的素材通常是流水账,要翻译成"结果语言":

| 流水账素材 | 改写后 |
|-----------|--------|
| 这周一直在调 bug | 修复 XX 模块 3 个阻塞性缺陷,XX 功能于周四恢复上线,未影响客户交付 |
| 开了好几个会 | 与产品确认了 XX 需求边界,砍掉 2 个低优先级功能,开发范围缩小约 30% |
| 帮新来的同事熟悉项目 | 完成 XX 的入职带教,其已能独立承接 XX 日常工单 |
| 方案被驳回了 | XX 方案按评审意见完成 v2,新增成本预估章节,预计下周二重新评审 |

规律:把**过程**翻译成**结果**,把**忙碌**翻译成**产出**,把**坏消息**翻译成**已处理的风险**。翻译不出来的(真的没产出),老实归入"问题与风险",并给出下周怎么破。

## 语气规则

- **不邀功**:"在我的推动下"→ 删掉主语吹捧,直接写事;功劳让协作者出现在句子里。
- **不甩锅**:"由于 A 团队未配合导致延期" → "跨团队依赖存在阻塞,已升级至 XX 寻求决策支持,当前预计延期 3 天"。写事实 + 已采取的行动,不写情绪和责任归属。
- **不承诺做不到的**:"下周完成全部开发"如果没把握,写"下周完成核心链路开发,联调视 XX 进度"。

## 字数与格式

周报 300~600 字,日报 100~200 字,月报 800~1500 字。超过就没人看。默认输出 Markdown;公司有固定模板时先问模板样式,按模板填。

## 示例

输入:"帮我写周报,这周:周一开了需求评审,周二周三在改上个版本的bug,周四方案写了一半被组长打回来一次,周五改完了"

输出(节选):

```
一、本周关键结果
1. XX 需求通过评审,开发范围明确(周一定稿,已排期下周)
2. 上版本 5 个缺陷全部修复并回归通过,X 功能恢复稳定(周三完成)
3. XX 方案 v2 完成并提交(按评审意见补充了异常场景和成本预估)

二、问题与风险
1. 方案 v1 评审时发现前期调研不足,已补做 XX 分析;同类问题下周起在方案前增加 30 分钟预沟通
2. (风险)XX 依赖的接口文档对方尚未提供,可能影响下周联调,已跟进,周一如未拿到将升级至双方组长

三、下周计划
1. 完成 XX 需求核心链路开发(周三)
2. XX 方案通过评审后启动排期(周二评审)
3. 跟进接口文档,启动联调准备

四、需要支持
暂无。(若接口文档周一未到位,需要组长协调)
```

注意这条:素材里"方案被打回来"是负面事实,输出里变成了"发现前期调研不足 + 已补做 + 流程改进"——没有隐瞒,但主动权在自己手里。

## 自检清单

- [ ] 每条结果都是结论先行,有量化或明确状态
- [ ] 每个风险都带应对方案或已采取的动作
- [ ] 下周计划可衡量("推进"“持续跟进”这类词已清除)
- [ ] 无甩锅句式、无情绪表达
- [ ] 长度在范围内
